# Спецификация media-converter

## Назначение

Автоматический локальный конвертер медиа-ресурсов для веб-сайтов. Мониторит директории, сжимает изображения и видео в web-оптимальные форматы, ведёт метрики экономии и предоставляет CLI для управления.

## Функциональные требования

### FR-1. Мониторинг файловой системы
Система должна отслеживать указанные директории на появление новых или изменённых файлов с расширениями `.jpg`, `.jpeg`, `.png`, `.mp4`, `.mov`.

### FR-2. Конвертация изображений
Система должна конвертировать изображения JPEG/PNG в форматы WebP и/или AVIF с настраиваемым качеством (1-100). При ошибке AVIF выполняется fallback на WebP.

### FR-3. Конвертация видео
Система должна перекодировать видео MP4/MOV в H.264 MP4 с настраиваемым CRF (0-51), удалять аудиодорожку и метаданные, добавлять флаг faststart для web-оптимизации.

### FR-4. Атомарная запись
Система должна записывать результаты конвертации атомарно: временный файл → rename → целевой файл, чтобы исключить повреждение при сбое.

### FR-5. Сбор метрик
Система должна вести учёт: количество обработанных файлов, суммарная экономия в байтах, процент сжатия для каждого файла, история последних 100 операций.

### FR-6. CLI-интерфейс
Система должна предоставлять команды: `start` (фоновый запуск), `stop` (остановка), `status` (проверка PID + метрики), `stats` (полная статистика), `config` (текущая конфигурация), `logs` (последние JSON-логи), `watch` (интерактивный дашборд).

### FR-7. Контейнеризация
Система должна запускаться в Docker-контейнере с монтированием volumes для media, output, settings.toml и logs.

## Нефункциональные требования

### NFR-1. Производительность
Конвертация изображений выполняется параллельно по форматам через ThreadPoolExecutor. Максимальное количество рабочих потоков настраивается.

### NFR-2. Надёжность
При ошибке обработки отдельного файла система логирует ошибку и продолжает работу. StateManager восстанавливается от повреждённого или отсутствующего state-файла.

### NFR-3. Потокобезопасность
StateManager использует threading.Lock для атомарных операций чтения/записи JSON-файла. Запись выполняется через временный файл и os.replace.

### NFR-4. Конфигурируемость
Все параметры (пути, качество, форматы, кодеки, workers) задаются через `settings.toml` и валидируются при старте.

## Границы системы

**Внутри системы:**
- Мониторинг файловой системы
- Конвертация изображений (Pillow)
- Конвертация видео (ffmpeg)
- Хранение метрик (JSON-файл)
- CLI (Typer + Rich)
- JSON-логирование

**Снаружи системы:**
- Файловая система хоста (монтирование через volumes)
- ffmpeg (внешний бинарный зависимость)
- Docker Engine (для контейнерного запуска)

## Предметная область

### Сущности

**MediaFile** — файл, подлежащий обработке. Атрибуты: путь, расширение, размер.

**ConversionResult** — результат конвертации. Атрибуты: целевой формат, путь результата, оригинальный размер, новый размер, экономия в байтах, процент сжатия.

**ConversionJob** — единица работы. Атрибуты: входной файл, тип (image/video), статус (active/completed/error).

**SystemState** — состояние системы. Атрибуты: версия, обработано файлов, сэкономлено байт, активные задачи, размер очереди, время обновления, история операций.

### Роли пользователей

**Разработчик/Администратор** — настраивает settings.toml, запускает сервис, мониторит метрики через CLI.

**Конечный пользователь (косвенно)** — получает оптимизированные медиафайлы для веб-сайта.
